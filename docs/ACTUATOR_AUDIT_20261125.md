# ACT-01 / EEPROM-01 / EVC-01 — architecture decision 25.11.2026

Baseline 519376b, RPi 0.7.0 observe_only. Scope approved: permanent EEPROM prohibition, source regression gate, Mode1 vs Mode8 and EVC audit. No actuator implementation, hardware write, configuration, restart or version bump. Main remains 0.6.39.

## Binding policy
Zero EEPROM/nonvolatile or unclassified device writes in the regulation loop, including inverter, EVC and other actuators. No generic write path, no fallback to persistent limits, including recovery. Infrequent configuration only by separately authorized procedure. Device persistence is distinct from local SQLite/HA evidence. Unknown storage or firmware mapping means deny. Never equate FC16 with volatile storage. Keep fixed breaker 25 A per phase, EV ceiling 16 A, no new hardware, existing night windows/algorithm. Approved policy does not authorize deployment or activation.

Vendor V001.00, SHA256 6ce05447c1b918bf0056eca6b8925102d8bd92f420fc384b25390b0c8bc712d7 ([PDF](https://github.com/user-attachments/files/23519710/SolaX.Hybrid.X1.X3.ESS.Modbus.RTU.V001.00-EN-250610.pdf)), printed p36: approximately one million EEPROM writes, starred changed settings saved after power off. p47: 0x24/0x25 charge/discharge max current, 0xE0 upper SOC starred. PeakShaving p40–42 also starred. Do not regulate with these or work mode/other static configuration. 5s for 2h daily = 525600 writes/year if each value changes; not actual endurance forecast. At 235.1 V, 0.1 A = 23.51 W DC, precision is not the issue.

Protocol version 100, Gen4 DSP1.62 ARM1.60-1.09, installed integration 2026.11.04. Mode1 p59–61 new FC16 A0–A7, FC03 read 1A0–1A7: mode, ExecMode, signed AC W LSW/MSW, signed AC var LSW/MSW, ExecDuration seconds, WaitTimeout (table unit W inconsistent with text/example seconds). Positive AC absorption; negative AC injection. p73 worked example confirms duration and timeout encoding. Mode8 p68–70: mode, ExecMode, unsigned PV limit, signed DC BAT W (negative charge), WaitTimeout, NextMotion. No independent ExecDuration in new layout. Mode1 has explicit execution time and waiting period, but what happens to output during waiting, zero timeout and actual native expiry are not proven for installed firmware. Both are VPP, not EEPROM marked; [integration Mode1 docs](https://homeassistant-solax-modbus.readthedocs.io/en/stable/solax-mode1-modbus-power-control/) independently describe volatile commands and normal-mode return. [Mode8 docs](https://homeassistant-solax-modbus.readthedocs.io/en/latest/solax-mode8-modbus-power-control/) describe duration issues. No automatic physical retry.

Installed plugin_solax.py build_direct_vpp_command uses legacy FC16 7C..88 for Mode1, 7C..8A for modes4–7, A0..A7 for Mode8/9; legacy stop 7C block of 13 zeros. New V001.00 A0 disable one zero. Vendor [legacy KB](https://kb.solaxpower.com/it/solution/detail/40289fdf9279482a01927a1743c40230) search index describes duration then timeout; live page returned HTTP500, firmware-specific support table not verified. Vendor PDF also lists old VPP block p74–76. Do not mix protocols or try alternate addresses after uncertain dispatch. Choose new A0 Mode1 as primary candidate only, not a qualified physical mapping; direct documented mapping matches protocol100, independently verify actual device readback before authorization. Mode8 stays archived/locked as fallback design, no parallel development. Mode6 recovery remains installed for Mode8 candidate but is not proof of physical recovery.

## Decision
Primary nocturnal actuator candidate: Mode1 AC absorption, no PV curtailment. Reuse existing AC phase-budget intent, model, telemetry, transport and evidence; adapt only boundary, power sign, readback, expiry, ownership and stop. Night PV=0 expected but measure it; positive inverter AC absorption is not exact battery DC charge. During PV production or EPS transitions or BMS limits, mapping/eligibility must be verified; do not infer DC power from command. AC target is inverter port, not total PCC/grid/house power. Do not subtract house load twice. Phase imbalance and conversion losses still matter; use measured grid phase currents, inverter AC and battery DC power, no assumption of equal phase distribution. Zero AC target is not proof of zero battery discharge. Before any automatic operation verify native expiry including waiting state, disable readback, local recovery independent of network, BMS/SOC limits, no discharge into EV, ownership and per-phase limits. Prior Ethernet carrier outage makes software stop over same network insufficient. Physical authorization remains NO-GO. No new hardware or repeated normal LCD test proposed. If native expiry cannot be established, stay observe_only; do not silently switch to Mode8 or persistent configuration.

## Wallbox
Actual installed solax_http entity max_charge_current_setting maps 0x668, plugin_solax_ev_charger.py HTTP write reg82, read Set[76]; observed 16A, firmware 1.18. Community report [#919](https://github.com/wills106/homeassistant-solax-modbus/discussions/919) reports persistence after restart for 0x668; classify persistent/unknown, forbidden in loop even though exact storage medium not independently proven. Historical LIVE v1 used it, retired package remains archived. Current grep of active automations.yaml/scripts.yaml found no matching current/limit writes in searched fields, not whole-system proof. Existing max 16A untouched. Vendor [EVC protocol V3.4](https://www.photovoltaikforum.com/core/file-download/476194/) documents 0x628 temporary current 0.01A, lost on power off; older 0x64F maximum retained. Screenshot fetch failed; extracted text and independent community test agree. Installed Modbus plugin Gen1 >=109/Gen2 exposes charge_current 0x628, native step 1A, scale .01; actual HA EVC exposes HTTP only among queried current entities, no qualified temporary actuator. No assumption Modbus firmware version equals HTTP FW, or address/unit availability. 0x628 is a candidate only; no timeout proof on loss of communications, no fallback to 0x668. Start/stop and other EVC settings require separate persistence classification. First architecture uses fixed EV ceiling, battery as fine actuator; active EV regulation stays disabled until temporary interface and safe stopping qualified. No claim fixed EV alone prevents 25A violations; if house+EV exceeds available phase capacity even at zero battery charge, battery-only controller cannot enforce breaker limit. Native breaker limit configured 25A, behavior not proven. Full live operation requires qualified independent EV curtailment/protection; do not use battery discharge to hide overload.

## Regression
CI source tripwire inventories known device-write/HA service call sites, fixes sole currently reviewed FC16 address A0, requires locked pilot and rejects generic writes and new service routes. This is a narrow static regression, not proof against arbitrary code, vendor internals or other HA automations. Actual pinned TCP loopback checks exact FC16 frame and rejects unauthorized payloads. No changes to runtime or physical service. A future reviewed adapter must update the allowlist with documented volatile semantics and transport tests.
