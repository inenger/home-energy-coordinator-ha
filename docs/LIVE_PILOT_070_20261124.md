## Mapping audit
Installed SolaX Modbus 2026.11.04; Gen4, DSP 1.62 / ARM 1.60-1.09.
The installed direct-VPP API may send a whole command when changing an individual active parameter.
The existing integration transport may retry a write after a lost response. Existing button autorepeat is not acceptable for an expiring intent.
Mode 8 A6/A7 definitions differ between revisions. The older manufacturer KB describes A6 duration / A7 remote-control timeout. The manufacturer-authored protocol V001.02 (public mirror, Mode 8 table, pp. 70–71) describes A6 WaitTimeout / A7 NextMotion, A1 execution mode (1 = interrupt), LSW-first 32-bit PV/battery targets, negative battery target for charging. Readback A6/A7 at 1A6/1A7 agrees with the installed integration diagnostic labels. A6 is NOT a guaranteed maximum execution duration. The applicability to this exact firmware and native expiration remain unverified.
- Manufacturer KB (older mapping): https://kb.solaxpower.com/es/solution/detail/828080819564dbfd019564ddac0a01da
- V001.02 manufacturer-authored public mirror: https://manuals.plus/m/fa795deca1bc0722a9caf0dac168765d889f6b36ca09043b0ac5b9c3a7803b79.pdf
- Integration warning about expiry/return to mode 6: https://homeassistant-solax-modbus.readthedocs.io/en/stable/solax-mode8-modbus-power-control/
The V001.02 candidate has a new mapping ID; old approvals are rejected. The real service is hard-locked in source (HARDWARE_DISPATCH_QUALIFIED=False), even if installed or armed. Only a separately reviewed change after firmware-specific confirmation and a safe recovery plan may unlock it. Synthetic one-shot tests do not unlock the actual service.
Do not infer timeout from a successful HA service response. Core-unit internal retry/cancellation behavior remains to be verified.
Stable HA states can have old source timestamps even with healthy communication. Direct read-only preflight is necessary; current phase reports still require actual fresh timestamps.

## Qualification gates
1. Obtain authoritative firmware-specific mapping and manufacturer-approved local recovery procedure before installing/enabling the candidate service.
2. Review patch and exact installed hashes; back up HA and vendor sources. Apply only with separate authorization, keep main/production unchanged until reviewed.
3. Operator at installation, EV physically disconnected, stable low PV, no competing scheduled automation, adequate phase reserve. No unattended test.
4. First supervised minimum-power single shot. Confirm actual mode, direction, DC power, grid phase readings, and autonomous return to original normal mode after expiry without renewal. Abort and recover locally using approved procedure if response is unexpected or uncertain. Do not repeat ambiguous commands.
5. Only after recorded hardware proof: qualify transport loss, recovery, AC/DC boundary, ownership and then controlled EV coexistence. Implement automatic bounded dispatch separately. LIVE-01/02 remain open.
