# Audit uzavřené noční relace · 0.6.18 · 2.11.2026

Zdrojový základ: 6f868e39c7e99373d66c7f0cee4dff59ec051596.
Audit nemění runtime, verzi, HA konfiguraci ani původní historii.
Provozní měření, souhrn s přesnými časy/energií a raw evidence zůstávají
pouze na RPi. Veřejně jsou obecné závěry, metodika a syntetické regrese;
provozní MEMORY ani soukromé hash manifesty se neposílají.

## Rozsah a závěr

Kontrola se týká skutečné uzavřené živé relace, nikoli příznivé zpětné
rekonstrukce. Ověřuje verzi během celého okna, původní SQLite řádky,
potvrzené transportní části a skutečný HA recorder přes servírovanou kartu.
Samostatně integruje výkon pouze do skutečných stopů, původní expiry a
konce okna a kontroluje SOC přes zmrazený bateriový model. Při delší mezeře
zahrne pouze doložený úsek do intervenujícího stopu; nepřemosťuje zbytek.

Opakovaná fragmentace přes logical_lease_expired se v auditované relaci
neobjevila. Integrita původních řádků i nezávislá energie/pokrytí/SOC
souhlasí. Nejde o univerzální důkaz bezchybnosti: zůstává lokální SQLite
chyba a samostatná ochranná blokace nekonzistentních fázových vstupů.

Nové atomické receipty a původní input/owner reporty umožňují kontrolu
doručení, času rozhodnutí, původních freshness mezí a správného night poll.
Použité deadline nepřesahují nejstarší vstupní platnost. Uložené SOC důkazy
mají platné hashe a nevykazují dostupnost modelu/prognózy až po rozhodnutí.

## Zbývající nálezy

**A18-N1 · provozní spolehlivost zápisu.**
OperationalError se objevila v cestě RAM observe → event → INSERT.
Kolektor neměl čekající worker failure. Jedná se o chybu lokálního
zpracování/zápisu, nikoli automaticky o výpadek čidel. Současná obecná
chybová cesta to zaznamenává jako collection_failure, bezpečně zastaví
návrh a po obnově pokračuje. Před ostrým řízením zůstává tato cesta
nedořešená; samotná oprava plánování nemění možnost selhání zápisu.

Nová syntetická regrese drží skutečný druhý SQLite writer na témže
souboru, vyvolá SQLITE_BUSY při stejném INSERT a prochází celou main
výjimkou, uloženým stopem, outboxem a následným zotavením. Test potvrzuje
možný mechanismus, **nedokazuje přesnou příčinu skutečné noční výjimky**.

**A18-N2 · chybějící podrobnost SQLite diagnostiky.**
Uložený health obsahuje třídu výjimky a stack, nikoli původní text nebo
sqlite_errorcode/sqlite_errorname. Proto se noční OperationalError nesmí
bez dalšího přejmenovat na prokázaný database-locked problém.
Vhodné následné řešení musí současně řešit obsluhu zápisové kolize
a zachování strukturovaného SQLite kódu bez zveřejňování soukromých dat.

**Kontrola fáze není ztracený senzor.**
Čerstvé numerické P/U/I mohou porušit konzistenční podmínku P/(U×|I|).
Taková blokace se musí odlišovat od chybějícího měření. Druhá syntetická
regrese ověřuje blokaci vybraného inverter current zdroje, zachování jeho
hodnoty v evidenci, oddělení diagnostického API current zdroje, přepravu
do monitorů a návrat až přes nové koherentní sady. Neoslabuje toleranci
ani nenahrazuje vybraný proud jiným čidlem.

## Meze a dohledatelnost

Skutečná měřená bateriová hodnota není modelový SOC/energie.
Modelové fázové limity nejsou certifikace jističe nebo transientů.
Podmíněné virtuální předání po skončení okna se nesmí zaměnit za přesnou
fyzickou obnovu ani samo o sobě označit jako novou poruchu.
Původní live source, rekonstrukce, priority, tarif i automatizace zůstávají.

Nové dvě syntetické regrese prošly. První fixture chybně očekávala vybraný
proud v diagnostickém grid_l1_a_reported; opravena byla assertion na
grid_l1_a a doplněna kontrola rozdílných zdrojových entit, nikoli produkční
mapování. Oba syntetické výsledky jsou v night-audit-evidence-0618/.
Pomocná analýza původně hledala model v nepoužité priority_sessions;
správný model se převzal z původního priority_samples.session a ověřila
se jeho dostupnost před převzetím řízení. Původní skript i chyba zůstávají
soukromě uchované. Nejde o chybějící zmrazený model.

Reader skutečného recorderu běžel samostatně s limitem paměti a guardem.
Neprováděl se Chromium zátěžový test ani restart služby. Publikace testů,
CI a merge se potvrzují samostatně v PR; auditní doplnění nezvyšuje runtime verzi.
